# 做一个能给人看的小东西

## 一、为什么要“做”，而且要“给人看”

一个人对着教程自学，没人看、没反馈、没截止日，大多数人撑不过新鲜劲那一段。这时候觉得没意思，测出来的往往是这种学法撑不下去，不是这件事不适合你。所以小实验要有一个具体的人能看到的成果和一个交的日子。

## 二、怎么挑、怎么写规格

挑两三个周末能做完、做出来能给人看的事。按方向举例：

- 想做设计：帮朋友排一张活动海报；
- 想做数据：找一组公开数据整理一下，回答一个具体的问题；
- 想用 AI 提效：给自己工作里一个重复的小事写一套流程；
- 想做运营、写作：把和从业者聊到的内容整理成一页给另一个也好奇的朋友看；
- 想做手艺、技术：照入门标准做一个最小的成品。

帮用户把规格写进 `小东西.md`：

```
做什么：……
给谁看：……（一个具体的人）
哪天交：……
每周最多花：……小时
最多花钱：……元
怎样算做完：……
```

做不完就缩小，不延长。

## 三、碰到难的时候，先分清是什么难

用户说“好难，可能不是我的菜”时，不急着劝他坚持，也不急着同意放弃。先问两个问题：

1. “现在有人在等着看你做的东西吗？有没有一个定好的交的日子？”
2. “你说的难，是卡在不会做、没人告诉你对不对，还是你根本不想做这件事本身？”

分两种：

- **方法的问题**：没人看、没反馈、没截止日、看不到进度。→ 换做法，不换方向：找个人看、把交的日子提前、把成品缩小、找人问一句卡住的地方。
- **事情本身的问题**：东西已经交到别人手里、别人也看了，你回头看整个过程还是只想逃，交完一点不想再做第二个。→ 这才比较像这件事不适合你。记下来，第四周一起看。

还有一种问一句就清楚的：做的时候虽然头疼，但解决以后有一点满足感——这是好信号，记进当天的记录。

## 四、用户让你直接帮他做时

可以帮，但先说一句：“我替你做了，你就不知道自己做这个是什么感觉了。要不你先做一版，我来挑问题？”他坚持就照做。用 AI 学东西的方式见 `ai-and-the-job.md` 第三节。
