# 还原和检查

## 还原（用户说“还原”）

1. 按日期顺序读所有碎片。
2. 拼成 `初稿.md`：
   - 只做顺序调整、合并重复、按事情分段；
   - 保留用户原话，口语也保留（检查阶段再改）；
   - 缺的东西标 `【待补：具体数字】`、`【待补：时间】`；
   - 碎片里的自我贬低不进正文，放在末尾“写的时候冒出来的话”，不评论。
3. 给用户看，只说：“这是你这几天写下的东西，拼起来了。”
4. 问：“要不要开始检查？要的话，给我一个具体的标准。”

## 检查（用户说“开始检查”）

先要一个具体标准。没有就帮他挑：“招聘页里你最想对上的是哪一条？”一次检查一条或一组。

输出三栏，写进 `检查.md`：

| 标准里的这一条 | 初稿里能对上的事实 | 处理 |
|---|---|---|
| 跨部门协作推动流程优化 | 退款对账：客服和财务天天吵，自己做了共享表，两天压到半天 | 对得上 → 改写：“牵头搭建客服—财务共享对账表，将退款核对周期由 2 天缩短至半天，覆盖大区半年” |
| 数据分析能力 | （没有） | 先放一边；问一句：有没有用数据做过判断的事？ |
| 结果量化 | 退款那件只有“周五不加班了” | 缺数据 → 去旧聊天记录或报表里查准确率、处理量 |

规则：
- 改写只用初稿里有的事实，不加形容词堆砌（“极强”“卓越”）。
- 对不上就写“先放一边”，不说“你缺乏……”。
- 每轮最后给下一步卡片。

## 四种常见文本的检查重点

- **简历**：每条经历能否对上岗位要求；有没有结果（数字、变化）；动词是不是自己做的事。
- **方案**：评审最关心的三个问题（为什么做、怎么做、要多少资源）各有没有答案；哪条论据缺数据。
- **论文/开题**：研究问题一句话说得清吗；每个部分对应哪条评审要求；引文是否都有出处。
- **年度总结/述职**：今年做成的三件事各有一个结果吗；明年计划是否接着这些结果。
